About the OR operators
- Use any data type
- Return any data type
- Short circuiting or short circuit evaluation

Short Circuiting JS
JS stops evaluating an expression as soon as it has enough info to determine the result

OR ( | | )
- returns the first truthy value
- If first value is falsy -> JS returns the ssecond value truthy

```javascript
const username = "" || "Guest";

console.log(username); // "Guest"
```

- JavaScript checks `""`.
- An empty string is falsy.
- JavaScript evaluates `"Guest"`.
- The result is `"Guest"`.

### What counts as falsy?

These are the main falsy values in JavaScript:

|Value|Falsy?|
|---|---|
|`false`|Yes|
|`0`|Yes|
|`""`|Yes|
|`null`|Yes|
|`undefined`|Yes|
|`NaN`|Yes|
|`true`, `1`, `"hello"`, `[]`, `{}`|No|

When should we use | | 
- Use Case 1 -> Provide fallback value
```javascript
const displayName = user.name || "Anonymous";
```

- Use case 2: Choose between alternatives
```javascript
const databaseUrl = process.env.DATABASE_URL || "localhost";
```

----
AND ( && )
- returns first falsy value
- last value if every operand is truthy
```javascript
const result = true && "Success";

console.log(result); // "Success"
```

Use case 3: Check data before using it

```javascript
if (user && user.profile) {
  console.log(user.profile.name);
}
```

JavaScript checks `user` first. If it is falsy, it never checks `user.profile`.

Use case 1: Run something only when a condition is true

```javascript
const isAuthenticated = true;

isAuthenticated && console.log("Welcome!");
```

The message prints only if `isAuthenticated` is truthy.

Nullish Coalescing (`??`)
returns the right-hand value only when the left-hand value is `null` or `undefined`.

```javascript
const count = 0 ?? 10;

console.log(count); // 0
```

Why? Because `0` is a valid value. It isn't `null` or `undefined`.

Compare that with OR:

```javascript
console.log(0 || 10); // 10
console.log(0 ?? 10); // 0
```

This is the key difference between the two operators.

Use case 1: Preserve valid numeric values

```javascript
const retryLimit = config.retryLimit ?? 3;
```

If `retryLimit` is `0`, it stays `0`. The fallback `3` is used only if the value is missing or `null`.

Use case 2: Preserve an intentional empty string

```javascript
const title = user.customTitle ?? "New User";
```

If `customTitle` is `""`, it stays empty. A fallback is used only for `null` or `undefined`.

Use case 3: Handle optional API data

```javascript
const page = request.page ?? 1;
const limit = request.limit ?? 20;
```

If a client sends `page: 0`, the value stays `0`. If it omits `page`, the default is `1`.
