## Short circuiting with `||` and `&&`

The logical operators `||` and `&&` have three properties worth knowing:

- They can **use** any data type.
- They can **return** any data type, not only `true` or `false`.
- They do **short circuiting** (also called short-circuit evaluation).

> [!definition] Short circuiting
> JavaScript stops evaluating an expression as soon as it has enough information to know the result.

### OR (`||`)

- Returns the **first truthy** value.
- If the first value is falsy, JavaScript moves on and returns the second value.

```javascript
const username = "" || "Guest";

console.log(username); // "Guest"
```

What happens step by step:

1. JavaScript checks `""`.
2. An empty string is falsy.
3. JavaScript evaluates `"Guest"`.
4. The result is `"Guest"`.

### What counts as falsy?

These are the main falsy values in JavaScript:

| Value | Falsy? |
|---|---|
| `false` | Yes |
| `0` | Yes |
| `""` | Yes |
| `null` | Yes |
| `undefined` | Yes |
| `NaN` | Yes |
| `true`, `1`, `"hello"`, `[]`, `{}` | No |

> [!warning] Empty arrays and objects are truthy
> `[]` and `{}` are **not** falsy, even though they're empty.

### When to use `||`

**Use case 1: Provide a fallback value**

```javascript
const displayName = user.name || "Anonymous";
```

**Use case 2: Choose between alternatives**

```javascript
const databaseUrl = process.env.DATABASE_URL || "localhost";
```

### AND (`&&`)

- Returns the **first falsy** value.
- Returns the **last** value if every operand is truthy.

```javascript
const result = true && "Success";

console.log(result); // "Success"
```

### When to use `&&`

**Use case 1: Check data before using it**

```javascript
if (user && user.profile) {
  console.log(user.profile.name);
}
```

JavaScript checks `user` first. If it's falsy, it never checks `user.profile`.

**Use case 2: Run something only when a condition is true**

```javascript
const isAuthenticated = true;

isAuthenticated && console.log("Welcome!");
```

The message prints only if `isAuthenticated` is truthy.

## Nullish coalescing (`??`)

> [!definition] Nullish coalescing (`??`)
> Returns the right-hand value **only** when the left-hand value is `null` or `undefined`. These two are called the *nullish* values.

```javascript
const count = 0 ?? 10;

console.log(count); // 0
```

Why `0`? Because `0` is a valid value. It isn't `null` or `undefined`.

Compare that with OR:

```javascript
console.log(0 || 10); // 10
console.log(0 ?? 10); // 0
```

> [!tip] The key difference
> `||` falls back on **any falsy** value (`0`, `""`, `false`...). `??` falls back **only** on `null` or `undefined`.

### When to use `??`

**Use case 1: Keep valid numeric values**

```javascript
const retryLimit = config.retryLimit ?? 3;
```

If `retryLimit` is `0`, it stays `0`. The fallback `3` is used only if the value is missing or `null`.

**Use case 2: Keep an intentional empty string**

```javascript
const title = user.customTitle ?? "New User";
```

If `customTitle` is `""`, it stays empty. The fallback is used only for `null` or `undefined`.

**Use case 3: Handle optional API data**

```javascript
const page = request.page ?? 1;
const limit = request.limit ?? 20;
```

If a client sends `page: 0`, the value stays `0`. If it leaves `page` out, the default is `1`.

## Spread vs rest (noticed in the coding challenge)

> [!definition] Spread (`...` on the right side / in a value)
> Unpacks an array into its individual elements.

```javascript
const allPlayers = [...players1, ...players2];
```

The names from `players1` are added as separate names, not as a nested array. The same goes for `players2`.

> [!definition] Rest parameter (`...` in a function's parameters)
> Collects any number of arguments into one array.

```javascript
const printGoals = function (...players) {
  console.log(players);
};

printGoals("Messi", "Ronaldo", "Salah");
// ["Messi", "Ronaldo", "Salah"]
```

Whatever arguments you pass end up packed into the `players` array.

## Looping arrays: the `for...of` loop

> [!definition] `for...of`
> Loops over an array one element at a time, giving you each element directly.

```javascript
const menu = ["Pizza", "Pasta", "Risotto"];

for (const item of menu) console.log(item);
// Pizza
// Pasta
// Risotto
```

### Getting the index too: `.entries()`

`menu.entries()` gives each element as an `[index, element]` pair:

```javascript
for (const item of menu.entries()) {
  console.log(item);
}
// [ 0, 'Pizza' ]
// [ 1, 'Pasta' ]
// [ 2, 'Risotto' ]
```

Destructure the pair straight in the loop to get clean variables:

```javascript
for (const [i, el] of menu.entries()) {
  console.log(`${i}: ${el}`);
}
// 0: Pizza
// 1: Pasta
// 2: Risotto
```

## Enhanced object literals

ES6 lets you put an existing object inside another object without writing the property name twice.

```javascript
const weekDays = ["mon", "tue", "wed", "thu", "fri", "sat", "sun"];

const openingHours = {
  [weekDays[3]]: {
    open: 12,
    close: 22,
  },
  [weekDays[4]]: {
    open: 11,
    close: 23,
  },
  [weekDays[5]]: {
    open: 0, // Open 24 hours
    close: 24,
  },
};

const restaurant = {
  name: "Classico Italiano",
  location: "Via Angelo Tavanti 23, Firenze, Italy",
  categories: ["Italian", "Pizzeria", "Vegetarian", "Organic"],
  starterMenu: ["Focaccia", "Bruschetta", "Garlic Bread", "Caprese Salad"],
  mainMenu: ["Pizza", "Pasta", "Risotto"],
  // ES6 enhanced object literals
  openingHours,
  order(starterIndex, mainIndex) {
    return [this.starterMenu[starterIndex], this.mainMenu[mainIndex]];
  },
};
```

Writing `openingHours,` replaces `openingHours: openingHours`.

The example also uses two more ES6 shortcuts:

- **Computed property names:** `[weekDays[3]]` uses the value `"thu"` as the key.
- **Method shorthand:** `order(...) { ... }` instead of `order: function (...) { ... }`.

## Optional chaining (`?.`)

> [!definition] Optional chaining (`?.`)
> Reads a property only if the thing before `?.` exists. If it's `null` or `undefined`, the expression stops and returns `undefined` instead of throwing an error.

The restaurant object for these examples:

```javascript
"use strict";

const restaurant = {
  name: "Classico Italiano",
  location: "Via Angelo Tavanti 23, Firenze, Italy",
  categories: ["Italian", "Pizzeria", "Vegetarian", "Organic"],
  starterMenu: ["Focaccia", "Bruschetta", "Garlic Bread", "Caprese Salad"],
  mainMenu: ["Pizza", "Pasta", "Risotto"],
  order: function (starterIndex, mainIndex) {
    return [this.starterMenu[starterIndex], this.mainMenu[mainIndex]];
  },
  openingHours: {
    thu: {
      open: 12,
      close: 22,
    },
    fri: {
      open: 11,
      close: 23,
    },
    sat: {
      open: 0, // Open 24 hours
      close: 24,
    },
  },
};
```

### Without vs with optional chaining

```javascript
// WITHOUT optional chaining
if (restaurant.openingHours && restaurant.openingHours.mon) {
  console.log(restaurant.openingHours.mon.open);
}

// WITH optional chaining
console.log(restaurant.openingHours.mon?.open);
console.log(restaurant.openingHours?.mon?.open);
```

### Example: looping over the week

```javascript
const weekDays = ["mon", "tue", "wed", "thu", "fri", "sat", "sun"];

for (const day of weekDays) {
  const open = restaurant.openingHours[day]?.open ?? "closed";
  console.log(`On ${day}, we open at ${open}`);
}
```

> [!tip] `?.` and `??` work well together
> `?.` returns `undefined` for missing days, and `??` turns that into `"closed"`. Using `??` instead of `||` matters here: Saturday opens at `0`, and `||` would wrongly turn that into `"closed"`.

### On methods

Check that a method exists before calling it:

```javascript
console.log(restaurant.order?.(0, 1) ?? "Method does not exist");
console.log(restaurant.orderRisotto?.(0, 1) ?? "Method does not exist");
```

### On arrays

```javascript
const users = [{ name: "Jonas", email: "hello@jonas" }];

// Solution 1
console.log(users[0]?.name ?? "User array empty");

// Solution 2
if (users.length > 0) console.log(users[0].name);
else console.log("Users array empty");
```
