Talking about JS under the hood and what it offers:
High Level 
any computer needs resources , JS you don't have to manage any resources at all it does that for you, but not as fast or optimized as low level 

Garbage Collected 
it cleans the memory up for you so you don't have to

Interpreted or just in time compiled
the code is converted to machine code or compiled inside the JS engine

Multi Paradigm
a Pradigm -> an approach and mindset of structuring code which will direct your coding style and technique

the most popular paradigms are :
- Procedural programming -> What we have been doing
- OOP
- Functional Programming

Prototype based object oriented 
almost everyhting in the JS is an object except for primitive values such as numbers , strings , etc
but arrays for example as just objects and we already saw that in the practice , why can we use the push and pop methods for example on them its because of the prototypal inheritance bascially we create arrays from an array blueprint ,we create the array from a prototype and its like the blueprint for the arrays and that prototype contains all the array methods and then we inherit the methods from the prototype

First class functions
In a language with first class functions , functions are simply treated as variables, we can pass them into other functions and return them from functions

dynamic typed langugae 
so no data type definitions and types becomes known at runtime 

single threaded  & non blocking event loop
Concurrency model -> how the JS engine handles the multiple tasks happening at the same time 
why do we need that ?
because JS runs in one single thread so it can only do one thing at a time
but what if there is a long running task?
sounds like it would block the single thread, however we want non blocking behaviour 
how do we do that?
By using an event loop , takes long running tasks and executes them in the background and puts them back in the main thread once they are finished

## The javascript engine and runtime
JS engine -> program that executes the javascript code

an js engine always contain a call stack and a heap
the clal stack is where our code is executed using somethign called execution context
The heap is an unstructured memory pool which stores all the objects that our application needs

Now how is the code compiled to machine code so that its actually can be executed afterwards

we know that computer processor only understads the zeros and ones whcih is machine code

compilation = the entire code is converted into amchine code at once and writtten to binary file that can be executed by computer 

Source code -> compilation -> becomes machine code -> executed -> program running

interpreter = runs through the source code and runs or executes it line by line

Source code -> executed line by line -> program running

the interpreted languages are much slower that than the compiled ones

Modern JS now use a hybrid version of both worlds called
Just-in-time (JIT) compilation = entire code is converted to machine code at once and then executed immediately

difference between compilation and JIT 
compilation -> execution can happen anytime after the compilation 
JIT -> the execution happens immediately after compilation

So how it works :
JS code enters the engine and then the first step is parsing the code that entered (read the code) during that process the code is parsed into a data strcuture called abstarct syntax tree (AST) works by splitting each line of code into pieces that are meangiful to the language like the const or function keywords and then saving all these pieces into the tree in a structured way, this step also looks for any syntax errors which will be later be user to generarte he machine code

The next step is the compilation which it takes the AST code and comp;iles it into the machine code and then this machine code gets executed right away

The execution happens in the call stack 
Modern javascript engines have a very clever way of optimization strategies, what they do is to create a very unoptimized version of the mqachine code in the beginning just to have everything good and running, then in the background this code is being optimized and recompiled during the already running program execution and this can be done multiple times and the unoptimized codee gets replaced with the new optimized code,

all these happen in special threads that we cnat access from code
