### Hoisting in JS
We said that the execution context contains 
- Variable environment
- scope chain 
- `this` keyword

We finished the scope chain , now we are talking about Variable enviroement and how variables are actually created

In JS there is a mechanims called hoisting

hoisting: Makes some types of variables accessible/usable in the code before they are actually declared 
	- Variables lifted to the top the scope 

But thats what happens

Behind the scenes , before the execution the code is scanned for variable declaration and for each variable a new propert is created in the variable enviroment object

![[Pasted image 20261008175208.png]]

Think of JS as doing two steps whenever it starts running a scope
- Step 1: Set up the names declared in that scope 
- Step2: runs the statements in order

Look at this code:
```javascript
console.log(age);
var age = 21;
```

before running the first line , JS has noticed `var age` . it creates a variabel named `age` and gives it the stating value undefined

so the situation is , before any line runs 
```text
Variables:
  age → undefined
```

then it executes the code: 
1. `console.log(age)` → looks up `age`, finds `undefined`, and prints it.
2. `var age = 21` → assigns `21` to `age`.

“Prepares declarations” means creating the variables beforehand. It does not mean running their assignments beforehand.

Hoisiting means JS prepares declaration before it execute your code

so for function declarations 
- Hoisted : YES
- Initial value: Actual function 
- Scope: Block

```Javascript
greet(); // "Hello!"

function greet() {
  console.log("Hello!");
}
```

Before the first line runs, `greet` already refers to the function.
==🔴Preparing the function doesn’t execute its body. ==
**The `"Hello!"` is printed when `greet()` calls it.**

Var Variables 
- Hoisted: YES
- Intial value: undefined
- Scope: Function

```javascript 
console.log(age); // undefined

var age = 21;

console.log(age); // 21
```

the printed value will be undefined

Let and Const variables 
- Hoisted: NO
- Intial Value: `<unintialized>`,TDZ (Temporal Dead Zone)
- Scope: Block

```javascript
console.log(age);   //ReferenceError
let age = 21;
```

Accessing them throws a ==🔴ReferenceError==

JS knows the variables exists but its not intialized yet -> Access is forbidden untill the execution reaches its declaration

That inteval from entering the scope to reaching the declaration is TDZ (Temporal Dead Zone)

Funtion Expressions and arrows functions
They follow their vairables rules 

so if var:
```javascript
greet();   //TypeError: greet is not a function

var greet = function() {
	console.log("Hello!");
};
```

Here greet is intialized by `undefined` -> callin gundefined causes ==🔴TypeError==

if const:
```javascript
greet(); // ReferenceError: Cannot access greet before intilaization

const greet = () => {
	console.log("Hello!");
};
```
Here greet is still in the TDZ , the function gets assigned when the execution reaches the declaration line

- `var` is **function-scoped**: an ordinary `{ ... }` block doesn’t contain it.
- `let` and `const` are **block-scoped**: they stay inside their enclosing block.

```javascript
function example() {
  if (true) {
    var a = 1;
    let b = 2;
  }

  console.log(a); // 1
  console.log(b); // ReferenceError: b is not defined
}
```

- `var` starts as `undefined`; 
- `let` and `const` must wait for their declaration.

---
Why was TDZ actaully existing for?
- Because of this behaviour makes it easier to avoid and catch errors: acessing variables before declaration is bad practice and should be avoided
- To make the `const ` actually the way its suppose to, since we cant change the value of a const after intiallization we cant put it with undefined first and then assign there real value later

If hoisting is casuing all these problems why does it exist?
- To basically use functions before declaration

example of why using var is not best practice because of hoisting
```javascript
if (!numProdcuts) deleteShoppingCart();

var numProducts = 10;

function deleteShoppingCart() 
{
	console.log("All products are delted");

```

since the numProducts here is undefined becaused it was declared before the assignement so that will make that function get executed while in real life the numProducts is 10 not zero

`this` Keyword/Variable
- Special variable that is created for every execution  context (every function).
- Takes the value of (points to) the "owner" of the function in which the `this` keyword is used

`this` is ==🔴NOT STATIC== .
It depends on **how** the function is called and its value is only asssigned when the function is actually called

We have 4 methods of fucntion calling
1. Method 
As a func attached to an object so when we call a method , `this` keyword is used to point on the object calling the method

`this` = `<Object that is calling the method>`

```javascript
const jonas = {
	name: 'Jonas',
	year: 1989,
	calcAge: function() {
		return 2037 - this.year;
	}
}

jonas.calcAge(); // 48
```

2. Simple functional call 
as normal functions where
`this` = undefined      (only in strict mode)

3. Arrow functions
arrow function dont get their own `this` keyword
so if you basically use the `this` keyword whenver you use the arrow function its basicllay pointing to the `this` of surrounding function

`this` = `<this of surrounding function`

4. Event listener 
this = `<DOM element that the handler is attached to>`

>[!note]
>`this` does not point on the **function** , or the function variable enviroement
