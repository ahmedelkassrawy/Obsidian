# 10 — Async SQLAlchemy

> [!info] Source
> Your section 10, plus README §7 "Asynchronous Operations". Back to [[00 - Index]] · Previous: [[09 - Querying Data]]

## The one-sentence version

Swap `create_engine` → `create_async_engine`, `Session` → `AsyncSession`, `sessionmaker` → `async_sessionmaker`, use `select()` instead of `query()`, and `await` every call that touches the DB.

## Why

Everything in earlier notes is the **sync** API. A sync DB call blocks the thread. Inside an async FastAPI endpoint (`async def`) that blocks the **event loop** — every other request waits. The async layer (`sqlalchemy.ext.asyncio`) makes queries, inserts, commits and refreshes non-blocking.

## Libraries involved

| Library | Purpose |
|---|---|
| `sqlalchemy` + `sqlalchemy.ext.asyncio` | ORM and async database layer |
| async driver: `asyncpg` (Postgres), `aiosqlite` (SQLite), `aiomysql` (MySQL) | The driver must be async too |
| `fastapi` | Async dependency injection via `Depends` |
| `pydantic` | Request/response models — unrelated to DB I/O |
| `databases` (optional, not used) | Alternative lightweight async wrapper |

```bash
pip install sqlalchemy asyncpg       # Postgres
pip install sqlalchemy aiosqlite     # SQLite
```

## Setup

```python
# database.py
from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession, async_sessionmaker
from sqlalchemy import select

DATABASE_URL = "postgresql+asyncpg://user:password@localhost/dbname"
# SQLite: "sqlite+aiosqlite:///./test.db"

async_engine = create_async_engine(DATABASE_URL, echo=False)
```

### 10.1 Creating an async session

```python
AsyncSessionLocal = async_sessionmaker(
    async_engine,
    class_=AsyncSession,
    expire_on_commit=False,
)
```

- Library: `sqlalchemy.ext.asyncio`
- Creates an **async session factory** so `async with AsyncSessionLocal()` opens a DB session asynchronously.
- **Keep `expire_on_commit=False`.** With the default (`True`), every attribute is expired after `commit()` and the next access tries to lazy-load — which needs an `await` that plain attribute access can't do → `MissingGreenlet` error. `False` keeps the loaded values.

### 10.2 Dependency injection for DB

```python
async def get_db():
    async with AsyncSessionLocal() as session:
        yield session
```

- Library: `fastapi` + `sqlalchemy.ext.asyncio`
- Yields one `AsyncSession` per request. `async with` closes it afterwards. Same shape as the sync `get_db` in [[05 - Sessions and sessionmaker]], just `async`.

Usage in an endpoint:

```python
from fastapi import Depends
from sqlalchemy.ext.asyncio import AsyncSession

@app.get("/users/{user_id}")
async def read_user(user_id: int, db: AsyncSession = Depends(get_db)):
    ...
```

### 10.3 Executing queries (SELECT)

```python
result = await db.execute(select(Order).filter(Order.order_id == order_data["order_id"]))
```

- Library: `sqlalchemy` — runs an async SELECT without blocking the event loop.
- General pattern: `result = await db.execute(select(Model).where(Model.field == value))`
- `.filter()` and `.where()` are synonyms on `select()`.
- **`db.query()` does not exist on `AsyncSession`.** Always `select()`.

### 10.4 Fetching one result

```python
existing = result.scalar_one_or_none()
```

- One ORM object or `None`; raises if more than one.
- Alternatives: `result.scalars().all()` → list; `result.scalar_one()` → exactly one or raise.
- Note: the **fetch** methods are sync (no `await`) — the I/O already happened in `execute`.

### 10.5 Adding a new record

```python
new_record = Model(**data)
db.add(new_record)
```

- `add` is sync (it only stages the object). The INSERT happens at `commit()`.

### 10.6 Committing changes

```python
await db.commit()
```

- Finalises INSERT/UPDATE/DELETE. Forget the `await` → coroutine never runs → nothing persists, and Python warns "coroutine was never awaited".

### 10.7 Refreshing an object

```python
await db.refresh(obj)
```

- Reloads the row (e.g. to get the autogenerated id / server defaults).

### 10.8 Reading data (GET)

```python
result = await db.execute(select(Complaint).filter(Complaint.id == complaint_id))
complaint = result.scalar_one_or_none()

# many
results = (await db.execute(select(Complaint))).scalars().all()
```

### 10.9 Updating data

```python
obj.field = new_value
await db.commit()
```

Assign on the ORM object, then commit — same as sync, just awaited.

### 10.10 Startup data initialisation

```python
@app.on_event("startup")
async def startup_event():
    async with AsyncSessionLocal() as db:
        await init_sample_data(db)
```

- Runs DB logic once at app start (e.g. pre-populate if empty).
- `@app.on_event` is deprecated in newer FastAPI; the replacement is a `lifespan` context manager:

```python
from contextlib import asynccontextmanager

@asynccontextmanager
async def lifespan(app):
    async with AsyncSessionLocal() as db:
        await init_sample_data(db)
    yield

app = FastAPI(lifespan=lifespan)
```

### Creating tables async

`Base.metadata.create_all` is sync; run it through `run_sync`:

```python
async with async_engine.begin() as conn:
    await conn.run_sync(Base.metadata.create_all)
```

## Relationships in async — the big trap

Lazy loading (`user.products` triggering a hidden SELECT) **cannot** work in async: attribute access can't `await`. You get `sqlalchemy.exc.MissingGreenlet`. Options:

1. Eager-load in the query: `select(User).options(selectinload(User.products))`.
2. Declare it on the model: `relationship("Product", lazy="selectin")`.
3. Explicit: `await db.refresh(user, attribute_names=["products"])`.

See [[07 - Relationships One-to-Many#Lazy loading and the N+1 problem]].

## Async summary table

| Operation | Example | Library | Description |
|---|---|---|---|
| Create async engine | `create_async_engine(url)` | `sqlalchemy.ext.asyncio` | Needs an async driver URL |
| Create async session factory | `async_sessionmaker(...)` | `sqlalchemy.ext.asyncio` | Factory for async sessions |
| Get DB session | `async def get_db()` | `fastapi`, `sqlalchemy.ext.asyncio` | Dependency for injecting sessions |
| Execute query | `await db.execute(select(...))` | `sqlalchemy` | Async SELECT/UPDATE/DELETE |
| Fetch result | `.scalar_one_or_none()` / `.scalars().all()` | `sqlalchemy` | Sync — no await |
| Add record | `db.add(obj)` | `sqlalchemy` | Sync — stages only |
| Commit | `await db.commit()` | `sqlalchemy.ext.asyncio` | Writes changes |
| Refresh | `await db.refresh(obj)` | `sqlalchemy.ext.asyncio` | Reload latest state |
| Update field | `obj.field = value` then `await db.commit()` | | Modify then commit |
| Create tables | `await conn.run_sync(Base.metadata.create_all)` | `sqlalchemy.ext.asyncio` | Bridge sync DDL |
| Startup init | `lifespan` / `on_event("startup")` | `fastapi` | Async DB logic at app start |

> In short: all async DB actions come from `sqlalchemy.ext.asyncio` and use `await` to avoid blocking FastAPI's event loop. Fetch/add are sync; execute/commit/refresh/close are awaited.

## Sync vs async side by side

```python
# sync
def read_user(user_id: int, db: Session = Depends(get_db)):
    return db.query(User).filter(User.id == user_id).first()

# async
async def read_user(user_id: int, db: AsyncSession = Depends(get_db)):
    result = await db.execute(select(User).where(User.id == user_id))
    return result.scalar_one_or_none()
```
