### Caching
If you have multiple users requesting the same data, repeating the same operations can be wasteful. 

Instead, you can use caching techniques for storing and retrieving frequently accessed data to help you optimize your services by:
- speeding up response times
- reducing server load 
- saving bandwidth 
- operational costs

Keyword Cache
simple caching mecahnims for storing the functions and endpoints answers by using the same exact match (key - value pair)

Fastapi cache can help in cahching functions and endpoints , give you the option to add Redis for centralizing the cache storing

```python
from contextlib import asynccontextmanager
from fastapi import APIRouter,FastAPI
from fastapi_cache import FastAPICache
from fastapi_cache.backends.inmemory import InMemoryBackend
from fastapi_cache.decorator import cache

router = APIRouter(prefix = "/generate",tags = ["Resource"])

#STandalone function cahcing
@cache(expire = 60)
async def classify_document(title:str) -> str:
	return f"Clasiified: {title}"
	
#Endpoint caching: @router decrotor on top 
@cache directly above the def
@router.post("/text")
@cache(expire = 60)
async def serve_text_to_text_controller():
	result = await classify_document("Report A")
	return {
		"result": result
	}
	
#Lifespan setup
async def lifespan(app:FastAPI):
	FastAPICache.init(InMemoryBackend(),prefix = "fastapi-cache")
	yield
	
app = FastAPI(lifespan = lifespan)
app.include_router
```

- async context manager -> FastAPI use this pattern to manage application startup and shutdown events

- `FastAPICache`: The central manager that manages the caching configuration.

- `cache`: The decorator applied to functions or endpoints to cache their return values.

These cache control headers instruct clients how to cache the responses on their side by specifying a set of directives

These are a few common cache control directives when sending responses:
- max-age -> defines max amount of time that a response is considered fresh
- no-cache -> forces revalidation so that the clients check for constant updates with the server
- no-store -> prevents caching entirely
- prviate -> stores responses in a private cache

### Semantic Caching
Semantic caching is a caching mechanism that returns a stored value based on similar inputs

Under the hood, the system uses encoders and embedding vectors to capture semantics and meanings of inputs. 

It then performs similarity searches across stored key-value pairs to return a cached response

Within a typical RAG system, there are two places where having a cache can reduce resource-intensive and time-consuming operations:
- Before the LLM to return a cached response instead of generating a new one
- Before the vector store to enrich prompts with cached documents instead of searching and retrieving fresh ones

### Model Quantization
adjustment process on the model weights and activations where high precision model para, are projected into lower-precision through values through fine-tuning operations using scaling factors on the original param distribution

You can then perform all critical inference operations with lower precision, after which you can convert outputs to higher precision to maintain the quality while improving perf

Reducing precision also decreases the memory storage requirements , theoretically lowering energy consumption and speeding up operations like matrix multiplication 

![[Pasted image 20261005165152.png]]

You can save as low-precision data types as 8 bit integer would require significatly less RAM per param than data type like 32-bit float

Precision versus quality trade-off
compare non quantized model and quantized model

![[Pasted image 20261005165329.png]]

Instead of 32-float you can select one of these formats:
- 16 bit floating point (FP16) -> cuts memory usage in half without much of a hit to model output quality
- 8-bit integer (INT8) -> offer huge savings in memory but with loss in quality
- 16-bit brain floating point (BFLOAT16) -> similar to FP32 balances memory and quality trade off
- 4-bit integer (INT4) -> provide balance bet memory effiency and computional presicison , making it better for low power devices
- 1-bit integer (INT1) -> use lowest precision data type with max model size reduction

- Performance improvement with INT32 or FP16 is not significant.
- The most popular lower-precision data type is INT8 for inference.

### Floating point numbers
why projecting 32-bit floats to other formats would save so much in GPU memory:

a 32-bit floating point numbers consists of the following types of bits:
- Sign bit describing whether a number is + or -
- Exponent bit -> controlling the scale of the number
- Mantissa bit -> holding the actual digits determing its precision

when you project FP32 numbers into other formats , you're squeezing it into smaller ranges , losing most of its mantissa bit and adjusting its exponent but without losing much of precision

However, while quantization saves memory, it can also reduce the inference speed of LLMs

How to quantize pretrained LLMs 
Quantization is the process of compressing large models by weight adjustment

One such technique is called GPTQ can qunatize LLMs with 175B param in 4hrs -> reducing bit width to 3 or 4 bits per weight and negliable accuracy drop

With the GPTQ quantization, you can quantize your favorite language model to 8, 4, 3, or even 2 bits without a big drop in performance, while maintaining faster inference speeds that are supported by most GPT hardware.

```python
import torch
from optimum.gptq import GPTQuantizer
from transformers import AutoModelForCasualLM,AutoTokenizer

model_name = "facebook/opt-125m"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name, 
								torch_dtype=torch.float16)
								
quantizer = GPTQuantizer(
	bits = 4,
	dataset = "c4",
	block_name_to_quantize = "model.decoder.layers",
	model_seqlen = 2048
)

quantized_model = quantizer.quantize_model(model, tokenizer)
```

### Fine Tuning
- You have significant token usage costs—for instance, due to requiring extensive system instructions or providing lots of examples in every prompt. 
- Your use case relies on specialized domain expertise that the model needs to learn. 
- You need to reduce the number of hallucinations in responses with a more fine tuned conservative model. 
- You require higher-quality responses and have sufficient data for fine-tuning. 
- You require lower latency in responses

How to fine-tune a pretrained model 
For any fine-tuning job, you will need to follow these steps: 
1. Prepare and upload training data. 
2. Submit a fine-tuning training job. 
3. Evaluate and use fine-tuned model.
