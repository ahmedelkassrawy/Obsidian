## Step 0 — Know your SDK version first

The server class was renamed between versions. Picking the wrong name is the classic `cannot import name` crash. Check what you have before writing anything:

```bash
python -c "import mcp; print(mcp.__version__)"
```

- **v1** (`mcp` 1.x): `from mcp.server.fastmcp import FastMCP`, and `FastMCP("name")`. It has no `version=` argument.
- **v2** (`mcp` 2.x): `from mcp.server import MCPServer`, and `MCPServer("name")`. It takes `version=` and `log_level=`.

The rest of this tutorial is v2. If you're on v1, only the import line and the class name change; everything else is identical.

## Step 1 — Create the server object

This is the whole server in one object. You'll hang every tool off it. Nothing runs yet.

```python
from mcp.server import MCPServer

mcp = MCPServer("Personal Task")   # add log_level="DEBUG" if you want to see your logs
```

## Step 2 — Define the data shape

Use a Pydantic model for a task. The type hints here double as validation, and later they let the SDK build the tool schema for free.

```python
from pydantic import BaseModel

class Task(BaseModel):
    id: int
    text: str
    done: bool = False
```

## Step 3 — Set up logging (not print)

Note: never use `print()` in an MCP server. It runs over stdio, and stdout is the protocol wire, so a `print` corrupts the messages. Use `logging`, which writes to stderr. The split to remember: **`logger.*` is for you watching the terminal, the `return` value is the only thing the model sees.**

```python
import logging

logger = logging.getLogger(__name__)
```

## Step 4 — Add your first tool (add-task)

A tool is just a function with `@mcp.tool("name")`. The docstring becomes the description the model reads, and the argument type hints become the input schema. No manual JSON schema.

Two traps live in this one function:
- `global nextid` is needed because we **reassign** `nextid` (`nextid += 1`). Any module variable you reassign inside a function needs `global`, or Python raises `UnboundLocalError`.
- Assign `id = nextid` first, then do `nextid += 1`. If you increment before using it (or add `+1` in two places) your first task id gets skipped.

```python
tasks = []

@mcp.tool("add-task")
def add_task(text: str):
    """Add a new task to the list of tasks."""
    global nextid
    task = Task(id=nextid, text=text, done=False)
    tasks.append(task)     # .append mutates in place, so no `global tasks` needed here
    nextid += 1
    save_tasks()
    return task            # returning the task = the model sees its fields
```

## Step 5 — List, complete, edit

Note: in `complete-task` and `edit-task`, **return inside the loop the moment you find the match.** If you loop and return after the loop, you hand back the *last* task instead of the matched one, and you crash with `NameError` when the list is empty. Return `None` after the loop for "not found".

```python
@mcp.tool("list-tasks")
def list_tasks():
    """List all tasks."""
    return tasks

@mcp.tool("complete-task")
def complete_task(task_id: int):
    """Complete a task by its ID."""
    for task in tasks:
        if task.id == task_id:
            task.done = True     # mutating a field, so no `global` needed
            save_tasks()
            return task          # <-- return INSIDE the loop
    return None                  # not found

@mcp.tool("edit-task")
def edit_task(task_id: int, new_text: str):
    """Edit a task by its ID."""
    for task in tasks:
        if task.id == task_id:
            task.text = new_text
            save_tasks()
            return task
    return None
```

## Step 6 — Clear completed tasks

Note: never remove items from a list while you loop over it, it skips elements. Rebuild the list with a comprehension instead. This is safe and also easy to read.

```python
@mcp.tool("clear-completed-tasks")
def clear_completed_tasks():
    """Clear all completed tasks."""
    global tasks                 # we REASSIGN tasks here, so `global` is required
    before = len(tasks)
    tasks = [task for task in tasks if not task.done]
    save_tasks()
    return f"Cleared {before - len(tasks)} completed tasks."
```

## Step 7 — Save to a file

Note: Pydantic v2 uses `model_dump()`, not the deprecated `dict()`. Wrap the write in try/except so a disk error is logged, not a crash.

```python
import json

TASK_FILE = "tasks.json"

def save_tasks():
    """Save the current list of tasks to a file."""
    try:
        with open(TASK_FILE, "w") as f:
            json.dump([task.model_dump() for task in tasks], f)
    except Exception as e:
        logger.error(f"Error saving tasks: {e}")
```

## Step 8 — Load on startup

Note: "startup" means import time. A bare call like `load_tasks()` at the left margin (not inside a `def`) runs the moment the file is imported, which is when the server boots. Only a `FileNotFoundError` (first run, no file yet) is the normal case, so treat that as info, not an error.

Note: this function needs `global tasks, max_id` because it reassigns both.

```python
tasks = []
max_id = 0

def load_tasks():
    """Load the list of tasks from a file."""
    global tasks, max_id
    try:
        with open(TASK_FILE, "r") as f:
            tasks = [Task(**task) for task in json.load(f)]
        for task in tasks:
            if task.id > max_id:
                max_id = task.id
    except FileNotFoundError:
        tasks = []
        logger.info("No task file found. Starting empty.")
```

## Step 9 — Wire startup at the bottom

Note: order matters. `load_tasks()` must sit at the BOTTOM, after the function is defined and after `tasks`/`max_id` exist. Then set `nextid = max_id + 1` on the next line so the first new id continues after the loaded tasks. Flip these two lines and `nextid` uses the old `max_id = 0`.

```python
load_tasks()
nextid = max_id + 1
```

## Step 10 — Run it

Note (Windows + base conda, no venv): install the CLI once with `pip install "mcp[cli]"` (that gives the `mcp` command and `typer`). Then:

```bash
# just run the server
mcp run D:\me\teach\mcp\server.py

# run it with the Inspector UI
npx @modelcontextprotocol/inspector mcp run D:\me\teach\mcp\server.py
```

Note: avoid `uv run mcp dev ...` on a base-conda setup. `mcp dev` builds a throwaway `uv run --with mcp` environment that installs plain `mcp` without the `[cli]` extra, so it dies with `Error: typer is required`. Launching the Inspector directly with `npx ... mcp run` uses your base-conda `mcp` (which has typer) and avoids that.

**Each MCP server should have one clear, well-defined purpose**

2. Defense in Depth Security Model
**Layer security controls throughout your architecture.**

**These class names are illustrative, not real SDK classes.** `JWTAuthHandler`, `CapabilityBasedACL`, etc. are things _you'd_ write (or pull from a library). It's a pattern to copy, not an import that exists.

```python
# Example: Multi-layer security implementation
class SecureMCPServer:
    def __init__(self):
        # Layer 1: Network isolation
        self.bind_address = "127.0.0.1"  # Local only
        
        # Layer 2: Authentication
        self.auth_handler = JWTAuthHandler()
        
        # Layer 3: Authorization
        self.permissions = CapabilityBasedACL()
        
        # Layer 4: Input validation
        self.validator = StrictSchemaValidator()
        
        # Layer 5: Output sanitization
        self.sanitizer = DataSanitizer()
    
    @authenticate
    @authorize(["read_files"])
    @validate_input
    @sanitize_output
    def read_file(self, path: str) -> str:
        # Business logic here
        pass
```

- **Network — `bind_address = "127.0.0.1"`.** The server only listens on the local machine, so nothing on the internet can even reach it. `127.0.0.1` = "this computer only." For a stdio server (like the one you built) this is basically free — it's not on a port at all. It matters when you expose a server over HTTP.

- **Authentication — `JWTAuthHandler`.** Proves _who_ is calling. A JWT is a signed token the caller presents; the server checks the signature to confirm the caller is who they claim. Answers "are you a real, known user?"

- **Authorization — `CapabilityBasedACL`.** Given a known caller, decides _what they're allowed to do_. ACL = access control list. "Capability-based" means permission is tied to a specific capability like `read_files`, not a broad admin flag. Answers "you're real, but are you allowed to do _this_?"

- **Input validation — `StrictSchemaValidator`.** Checks the arguments before running anything. Rejects a `path` that's the wrong type, or a path trying to escape to `../../etc/passwd`. Stops malformed or malicious input.

- **Output sanitization — `DataSanitizer`.** Cleans what you send _back_ so you don't leak secrets or return something harmful. Answers "is it safe to hand this result out?"

3. Fail Safe Design Patterns
**Design for graceful degradation under failure conditions.**

```python
class ResilientMCPServer:
	def __init__(self):
		self.circuit_breaker = CircuitBreaker(
			failure_threshold = 5,
			recovery_timeout = 30,
			expected_exception = DatabaseError
		)
		
		self.cache = RedisCache(ttl = 300)
		self.rate_limiter = TokenBucket(rate = 100,burst = 20)
	
	@circuit_breaker
	@cached(ttl = 300)
	@rate_limited
	def get_user_data(self,user_id:str):
		try:
			return self.database.get_user(user_id)
		except DatabaseErrror:
			return self.cache.get(f"user:{user_id}")
		except Exception as e:
			self.logger.error(f"Unexpected error: {e}")
			return {"error": "Service temporarily unavailable"}
```
