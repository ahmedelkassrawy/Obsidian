## Step 0 — Know your SDK version first

The server class was renamed between versions. Picking the wrong name is the classic `cannot import name` crash. Check what you have before writing anything:

```bash
python -c "import mcp; print(mcp.__version__)"
```

- **v1** (`mcp` 1.x): `from mcp.server.fastmcp import FastMCP`, and `FastMCP("name")`. It has no `version=` argument.
- **v2** (`mcp` 2.x): `from mcp.server import MCPServer`, and `MCPServer("name")`. It takes `version=` and `log_level=`.

The rest of this tutorial is v2. If you're on v1, only the import line and the class name change; everything else is identical.

## Step 1 — Create the server object

This is the whole server in one object. You'll hang every tool off it. Nothing runs yet.

```python
from mcp.server import MCPServer

mcp = MCPServer("Personal Task")   # add log_level="DEBUG" if you want to see your logs
```

## Step 2 — Define the data shape

Use a Pydantic model for a task. The type hints here double as validation, and later they let the SDK build the tool schema for free.

```python
from pydantic import BaseModel

class Task(BaseModel):
    id: int
    text: str
    done: bool = False
```

## Step 3 — Set up logging (not print)

Note: never use `print()` in an MCP server. It runs over stdio, and stdout is the protocol wire, so a `print` corrupts the messages. Use `logging`, which writes to stderr. The split to remember: **`logger.*` is for you watching the terminal, the `return` value is the only thing the model sees.**

```python
import logging

logger = logging.getLogger(__name__)
```

## Step 4 — Add your first tool (add-task)

A tool is just a function with `@mcp.tool("name")`. The docstring becomes the description the model reads, and the argument type hints become the input schema. No manual JSON schema.

Two traps live in this one function:
- `global nextid` is needed because we **reassign** `nextid` (`nextid += 1`). Any module variable you reassign inside a function needs `global`, or Python raises `UnboundLocalError`.
- Assign `id = nextid` first, then do `nextid += 1`. If you increment before using it (or add `+1` in two places) your first task id gets skipped.

```python
tasks = []

@mcp.tool("add-task")
def add_task(text: str):
    """Add a new task to the list of tasks."""
    global nextid
    task = Task(id=nextid, text=text, done=False)
    tasks.append(task)     # .append mutates in place, so no `global tasks` needed here
    nextid += 1
    save_tasks()
    return task            # returning the task = the model sees its fields
```

## Step 5 — List, complete, edit

Note: in `complete-task` and `edit-task`, **return inside the loop the moment you find the match.** If you loop and return after the loop, you hand back the *last* task instead of the matched one, and you crash with `NameError` when the list is empty. Return `None` after the loop for "not found".

```python
@mcp.tool("list-tasks")
def list_tasks():
    """List all tasks."""
    return tasks

@mcp.tool("complete-task")
def complete_task(task_id: int):
    """Complete a task by its ID."""
    for task in tasks:
        if task.id == task_id:
            task.done = True     # mutating a field, so no `global` needed
            save_tasks()
            return task          # <-- return INSIDE the loop
    return None                  # not found

@mcp.tool("edit-task")
def edit_task(task_id: int, new_text: str):
    """Edit a task by its ID."""
    for task in tasks:
        if task.id == task_id:
            task.text = new_text
            save_tasks()
            return task
    return None
```

## Step 6 — Clear completed tasks

Note: never remove items from a list while you loop over it, it skips elements. Rebuild the list with a comprehension instead. This is safe and also easy to read.

```python
@mcp.tool("clear-completed-tasks")
def clear_completed_tasks():
    """Clear all completed tasks."""
    global tasks                 # we REASSIGN tasks here, so `global` is required
    before = len(tasks)
    tasks = [task for task in tasks if not task.done]
    save_tasks()
    return f"Cleared {before - len(tasks)} completed tasks."
```

## Step 7 — Save to a file

Note: Pydantic v2 uses `model_dump()`, not the deprecated `dict()`. Wrap the write in try/except so a disk error is logged, not a crash.

```python
import json

TASK_FILE = "tasks.json"

def save_tasks():
    """Save the current list of tasks to a file."""
    try:
        with open(TASK_FILE, "w") as f:
            json.dump([task.model_dump() for task in tasks], f)
    except Exception as e:
        logger.error(f"Error saving tasks: {e}")
```

## Step 8 — Load on startup

Note: "startup" means import time. A bare call like `load_tasks()` at the left margin (not inside a `def`) runs the moment the file is imported, which is when the server boots. Only a `FileNotFoundError` (first run, no file yet) is the normal case, so treat that as info, not an error.

Note: this function needs `global tasks, max_id` because it reassigns both.

```python
tasks = []
max_id = 0

def load_tasks():
    """Load the list of tasks from a file."""
    global tasks, max_id
    try:
        with open(TASK_FILE, "r") as f:
            tasks = [Task(**task) for task in json.load(f)]
        for task in tasks:
            if task.id > max_id:
                max_id = task.id
    except FileNotFoundError:
        tasks = []
        logger.info("No task file found. Starting empty.")
```

## Step 9 — Wire startup at the bottom

Note: order matters. `load_tasks()` must sit at the BOTTOM, after the function is defined and after `tasks`/`max_id` exist. Then set `nextid = max_id + 1` on the next line so the first new id continues after the loaded tasks. Flip these two lines and `nextid` uses the old `max_id = 0`.

```python
load_tasks()
nextid = max_id + 1
```

2. Defense in Depth Security Model
**Layer security controls throughout your architecture.**

**These class names are illustrative, not real SDK classes.** `JWTAuthHandler`, `CapabilityBasedACL`, etc. are things _you'd_ write (or pull from a library). It's a pattern to copy, not an import that exists.

```python
# Example: Multi-layer security implementation
class SecureMCPServer:
    def __init__(self):
        # Layer 1: Network isolation
        self.bind_address = "127.0.0.1"  # Local only
        
        # Layer 2: Authentication
        self.auth_handler = JWTAuthHandler()
        
        # Layer 3: Authorization
        self.permissions = CapabilityBasedACL()
        
        # Layer 4: Input validation
        self.validator = StrictSchemaValidator()
        
        # Layer 5: Output sanitization
        self.sanitizer = DataSanitizer()
    
    @authenticate
    @authorize(["read_files"])
    @validate_input
    @sanitize_output
    def read_file(self, path: str) -> str:
        # Business logic here
        pass
```

- **Network — `bind_address = "127.0.0.1"`.** The server only listens on the local machine, so nothing on the internet can even reach it. `127.0.0.1` = "this computer only." For a stdio server (like the one you built) this is basically free — it's not on a port at all. It matters when you expose a server over HTTP.

- **Authentication — `JWTAuthHandler`.** Proves _who_ is calling. A JWT is a signed token the caller presents; the server checks the signature to confirm the caller is who they claim. Answers "are you a real, known user?"

- **Authorization — `CapabilityBasedACL`.** Given a known caller, decides _what they're allowed to do_. ACL = access control list. "Capability-based" means permission is tied to a specific capability like `read_files`, not a broad admin flag. Answers "you're real, but are you allowed to do _this_?"

- **Input validation — `StrictSchemaValidator`.** Checks the arguments before running anything. Rejects a `path` that's the wrong type, or a path trying to escape to `../../etc/passwd`. Stops malformed or malicious input.

- **Output sanitization — `DataSanitizer`.** Cleans what you send _back_ so you don't leak secrets or return something harmful. Answers "is it safe to hand this result out?"

2. ### Comprehensive Error Handling
**Implement structured error handling with proper classification.**

The idea: every failure gets sorted into a category so the caller knows _whose fault it is_ and _whether to retry_.

Three categories: 
- **client error** (the caller sent something bad, their fault)
- **server error** (your code/DB broke, your fault)
- **external error** (a dependency you rely on is down).

`MCPError` is a clean, structured shape: category, a short `code`, a human `message`, optional `details`, and `retry_after` (how many seconds before trying again).

```python
from enum import Enum
from dataclasses import dataclass

class ErrorCategory(Enum):
    CLIENT_ERROR = "client_error"      # 4xx - Client's fault
    SERVER_ERROR = "server_error"      # 5xx - Our fault
    EXTERNAL_ERROR = "external_error"  # 502/503 - Dependency fault

@dataclass
class MCPError:
    category: ErrorCategory
    code: str
    message: str
    details: Optional[Dict] = None
    retry_after: Optional[int] = None

class ErrorHandler:
    def handle_error(self, error: Exception) -> MCPError:
        if isinstance(error, ValidationError):
            return MCPError(
                category=ErrorCategory.CLIENT_ERROR,
                code="INVALID_INPUT",
                message="Request validation failed",
                details={"validation_errors": error.errors()}
            )
        elif isinstance(error, PermissionError):
            return MCPError(
                category=ErrorCategory.CLIENT_ERROR,
                code="ACCESS_DENIED",
                message="Insufficient permissions"
            )
        elif isinstance(error, DatabaseConnectionError):
            return MCPError(
                category=ErrorCategory.SERVER_ERROR,
                code="DATABASE_UNAVAILABLE",
                message="Database connection failed",
                retry_after=60
            )
        else:
            # Log unexpected errors for investigation
            self.logger.exception("Unexpected error occurred")
            return MCPError(
                category=ErrorCategory.SERVER_ERROR,
                code="INTERNAL_ERROR",
                message="An unexpected error occurred"
            )
```

3. Performance - reuse expensive things , cache repeats, don't block

Like the security example, the class names here (`ConnectionPool`, `MultiLevelCache`, `RedisCache`, `AsyncTaskQueue`) are illustrative patterns, not real SDK imports. You'd wire these from real libraries yourself.

**Connection pooling** (`db_pool`): opening a database connection is slow, so you keep a pool of 5–20 open ones and hand them out and back

**Multi-level cache**: check the fastest store first, fall back to slower/bigger ones. 
- L1 = in-memory (fast, tiny, 60s)
- L2 = Redis (shared across servers, 1h),
- L3 = database (durable, huge, 1 day).
A repeated query gets served from cache instead of recomputed.

**Async task queue**: for a heavy job, don't make the caller wait. `process_large_dataset` checks the cache; on a miss it submits the work to a background queue and immediately returns a `task_id` with `status: "processing"`.

```python
class PerformantMCPServer:
    def __init__(self):
        # Connection pooling
        self.db_pool = ConnectionPool(
            min_connections=5,
            max_connections=20,
            connection_timeout=30
        )
        
        # Caching strategy
        self.cache = MultiLevelCache([
            InMemoryCache(max_size=1000, ttl=60),      # L1: Fast, small
            RedisCache(ttl=3600),                      # L2: Shared, persistent
            DatabaseCache(ttl=86400)                   # L3: Durable, large
        ])
        
        # Async processing for heavy operations
        self.task_queue = AsyncTaskQueue(
            workers=4,
            max_queue_size=1000
        )
    
    async def process_large_dataset(self, query: str):
        # Check cache first
        cache_key = f"query:{hash(query)}"
        if cached_result := await self.cache.get(cache_key):
            return cached_result
        
        # Process asynchronously if not cached
        task = await self.task_queue.submit(
            self._execute_heavy_query,
            query
        )
        
        # Return immediately with task ID for polling
        return {
            "task_id": task.id,
            "status": "processing",
            "estimated_completion": task.estimated_completion
        }
```

Note the `:=` in `if cached_result := await self.cache.get(...)` — the walrus operator: assign and test in one line ("if there's a cached result, use it")

## Production Operations
Monitoring & observability — see what the server is doing

Two different things, both here:
**Metrics** (Prometheus) = numbers tracked over time. Three types, and the choice matters:

- `Counter` (`REQUEST_COUNT`) only ever goes up. Good for "total requests." The `labels(method, status)` let you slice it: requests per method, split by success vs error.

- `Histogram` (`REQUEST_DURATION`) records a distribution of values, so you can ask "what's my p95 request time." The `@REQUEST_DURATION.time()` decorator auto-times the function it wraps.

- `Gauge` (`ACTIVE_CONNECTIONS`) goes up _and_ down. Good for "how many connections right now."

**Structured logging** (structlog) = logs as key-value events, not flat strings. 
`logger.info("request_processed", method=..., duration=..., client_id=...)` writes a searchable record. Later you can query "every `request_failed` for `client_id=X`," which you can't do with plain text logs.

The pattern in `handle_request`: 
- on success, bump the success counter and log an info event; 
- on failure, bump the error counter, log an error event _with context_ (error type, client, duration), then `raise` again. 

Note it re-raises — it records the failure but doesn't swallow it.

Real libraries, by the way: `prometheus_client` and `structlog` are installable, unlike the illustrative class names in the earlier snippets.

```python
from prometheus_client import Counter, Histogram, Gauge
import structlog

# Metrics collection
REQUEST_COUNT = Counter('mcp_requests_total', 'Total requests', ['method', 'status'])
REQUEST_DURATION = Histogram('mcp_request_duration_seconds', 'Request duration')
ACTIVE_CONNECTIONS = Gauge('mcp_active_connections', 'Active connections')

# Structured logging
logger = structlog.get_logger()

class MonitoredMCPServer:
    @REQUEST_DURATION.time()
    def handle_request(self, request):
        start_time = time.time()
        
        try:
            # Process request
            result = self.process_request(request)
            
            # Record success metrics
            REQUEST_COUNT.labels(
                method=request.method,
                status='success'
            ).inc()
            
            # Structured logging
            logger.info(
                "request_processed",
                method=request.method,
                duration=time.time() - start_time,
                client_id=request.client_id,
                resource_count=len(result.get('resources', []))
            )
            
            return result
            
        except Exception as e:
            # Record error metrics
            REQUEST_COUNT.labels(
                method=request.method,
                status='error'
            ).inc()
            
            # Error logging with context
            logger.error(
                "request_failed",
                method=request.method,
                error=str(e),
                error_type=type(e).__name__,
                client_id=request.client_id,
                duration=time.time() - start_time
            )
            
            raise
```

2. Health checks — let an orchestrator know if the server is sick
A health endpoint is how a system like Kubernetes or a load balancer decides whether to send traffic to this instance or restart it.

Three states: 
`HEALTHY`, `DEGRADED` (working but something's off, e.g. cache slow), `UNHEALTHY` (broken).

`HealthMonitor` runs several sub-checks (database, cache, external API, disk, memory), times each one, and rolls them into one overall status. 

The rule: 
- any check `UNHEALTHY` → overall unhealthy; 
- any `DEGRADED` (and nothing worse) → degraded; else healthy.

It returns JSON with each check's status, message, response time, and a timestamp.
A failed check itself (an exception) counts as unhealthy, so the health system never crashes on a bad check.

```python
from enum import Enum
from dataclasses import dataclass
from typing import List

class HealthStatus(Enum):
    HEALTHY = "healthy"
    DEGRADED = "degraded"
    UNHEALTHY = "unhealthy"

@dataclass
class HealthCheck:
    name: str
    status: HealthStatus
    message: str
    response_time_ms: float
    last_checked: datetime

class HealthMonitor:
    def __init__(self):
        self.checks = [
            DatabaseHealthCheck(),
            CacheHealthCheck(),
            ExternalAPIHealthCheck(),
            DiskSpaceHealthCheck(),
            MemoryHealthCheck()
        ]
    
    async def get_health_status(self) -> Dict:
        results = []
        overall_status = HealthStatus.HEALTHY
        
        for check in self.checks:
            start_time = time.time()
            try:
                status = await check.check()
                response_time = (time.time() - start_time) * 1000
                
                results.append(HealthCheck(
                    name=check.name,
                    status=status,
                    message=check.get_message(),
                    response_time_ms=response_time,
                    last_checked=datetime.utcnow()
                ))
                
                # Determine overall status
                if status == HealthStatus.UNHEALTHY:
                    overall_status = HealthStatus.UNHEALTHY
                elif status == HealthStatus.DEGRADED and overall_status == HealthStatus.HEALTHY:
                    overall_status = HealthStatus.DEGRADED
                    
            except Exception as e:
                results.append(HealthCheck(
                    name=check.name,
                    status=HealthStatus.UNHEALTHY,
                    message=f"Health check failed: {e}",
                    response_time_ms=(time.time() - start_time) * 1000,
                    last_checked=datetime.utcnow()
                ))
                overall_status = HealthStatus.UNHEALTHY
        
        return {
            "status": overall_status.value,
            "checks": [asdict(check) for check in results],
            "timestamp": datetime.utcnow().isoformat()
        }
```
